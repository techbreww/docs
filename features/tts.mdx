TikTok Chat TTS reads eligible live-chat messages aloud through an OBS browser source or a browser player. It requires premium and works on personal and team servers. On team servers, the TTS Settings page requires server admin access.

## Set up TikTok TTS

1. Add a channel to [TikTok Chat Monitor](/features/live-monitor).
2. Open **Live Tools > TTS Settings > TikTok TTS > Live Source** and select the channel.
3. Open **TikTok Chat TTS** and turn on **Enable Chat TTS**.
4. Choose the trigger mode and audience, then set the voice and voice model in the **Voice** card at the top of the page.
5. Copy the **Hidden OBS Browser Source** URL into OBS, or open the browser player.
6. Send an eligible message in the selected live chat to test playback.

The live source is shared with Speed Tracker, Gift Race, [Gift Sounds](/features/gift-sounds), [Sticker Sounds](/features/sticker-sounds), and the TikTok [`!volume` command](/features/volume#volume-chat-command). Changing it changes the source those tools use too. [Twitch TTS](/features/twitch-tts) has separate settings, a separate source, and a separate queue, but uses the same voice.

## Trigger modes

| Mode | Behavior |
| --- | --- |
| **Use // prefix** | Eligible viewers start a message with `//`. |
| **Read messages normally** | Eligible messages can play without a prefix. |

**Allow Moderators Without //** lets moderators bypass the prefix requirement. Audience eligibility and trigger mode are separate checks.

```text
// Hello everyone, welcome to the stream!
```

## Audience and blocked users

Choose **Moderators** or **Everyone** as the audience. Additional controls let you grant or deny access:

- **Whitelisted Users** can use TTS even in moderator-only mode.
- **Allow MVP Profiles** grants eligibility to profiles currently on the MVP dock. In prefix mode, they still need `//` unless another applicable bypass grants it.
- **Heart Me TTS Access** grants eligibility to viewers with an active Heart Me fan-club badge. An inactive badge does not grant access. A new Heart Me gift can grant access for the current LIVE when badge status is unavailable.
- **Blocked Users** cannot trigger Chat TTS, even if they are moderators, whitelisted, MVPs, or otherwise eligible.

The selected trigger mode still applies to Heart Me access. **Heart Me Gift TTS** is a separate switch that reads a short announcement when someone sends that gift.

## Voices and audio tags

The **Voice** card at the top of **Live Tools > TTS Settings** applies to both TikTok and [Twitch TTS](/features/twitch-tts). Choose **Single voice** for a fixed voice or **Random voices** to select a premade voice per message. The saved single voice remains a fallback. Select **Browse** to search voices by name, accent, or style and play a short sample before choosing.

**Custom User Voices**, on the **TikTok Chat TTS** tab, assigns a fixed voice to a TikTok username and takes priority over the shared voice or random mode.

| Model | Use |
| --- | --- |
| **Eleven Multilingual v2** | General speech |
| **Eleven v3** | Expressive speech with audio tags |

With v3, try inline directions such as `[whispering]`, `[excited]`, or `[laughs]`. Delivery varies by voice and text; tags are prompts rather than guaranteed sound effects. See [TTS audio tags](/features/tts-audio-tags) for the full list of tags and tips.

```text
// [whispering] I have a secret. [laughs] We reached the goal!
```

Use [Gift Sounds](/features/gift-sounds) or [Sticker Sounds](/features/sticker-sounds) for a specific prerecorded sound clip.

## How messages are cleaned up

Before speaking, BrewBot converts stylized Unicode letters, such as 𝓑𝓻𝓮𝔀𝔀, ｆｕｌｌｗｉｄｔｈ, or Ⓑⓤⓑⓑⓛⓔ text, into plain letters. It skips emoji and decorative symbols such as ☆, ★, and ♡. Accents, other languages, and audio tags are kept.

A message with nothing left to say after cleanup, such as one made only of emoji, is skipped. The queue and player still show the original message.

## OBS playback

Copy the URL from the dashboard and keep the browser source active. It maintains the TikTok monitoring connection and plays queued audio. Configure browser-source audio routing in OBS so the sound reaches your stream. See [Stream overlays](/features/overlays).

The same source plays **Chat TTS**, announcements, **TTS Story**, **Gift Sounds**, and **Sticker Sounds**. You do not need an extra source for story narration, gift clips, or sticker clips. Gift Sounds and Sticker Sounds can run while chat reading is disabled. To set each kind of sound to a different level, use [Volume](/features/volume).

<Warning>
  Overlay and player links contain private access tokens. **Regenerate Link** replaces the token; update your OBS sources and saved player links afterward.
</Warning>

## Browser player

Select **Open Browser Player** to play TTS on a phone, tablet, or laptop with a visible queue. The player shows connection status, pending and active jobs, current playback, and recently played items. It provides volume, mute, pause-intake, skip, and clear controls where available.

If the browser blocks sound, select **Enable audio**. On iPhone or iPad, you can also use the [iOS app](/getting-started/ios-app) (beta). Use the player you intend to capture for the stream: it actively claims queued jobs, so opening another player or OBS source is not a way to mirror each message to every device.

## Queue and announcements

In **TTS Queue**, review pending and in-progress messages. **Clear Pending/Stale** removes pending items and playing items stuck for more than five minutes. **Overlay Connections** lists connected sources and lets you refresh or disconnect them.

Use **Send Announcement** for up to 300 characters of manual speech. A disconnected overlay leaves the announcement queued until a player reconnects. For longer reads, use [TTS Story](/features/tts-story), which accepts up to 20,000 characters.

<Note>
  TikTok TTS requests are unavailable while the Speed Tracker timer is running. Story parts also take priority over ordinary chat speech while pending or speaking. Check the timer, story queue, blocked list, and player connection when a chat message is not spoken.
</Note>

## Troubleshooting

| Symptom | Check |
| --- | --- |
| No messages are read | Confirm **Enable Chat TTS** is on and a live source is selected in **Live Source**. Messages from other monitored lives are ignored. |
| One message isn't read | Check the trigger mode and `//` prefix, the audience, and the blocked list. The same viewer sending the same message again within 30 seconds is skipped. |
| Nothing is read while the timer runs | New chat requests are skipped while the Speed Tracker timer is running. Messages sent during that time aren't queued for later. |
| An emoji-only message isn't read | Messages with no letters or numbers left after cleanup are skipped. See [How messages are cleaned up](#how-messages-are-cleaned-up). |
| No audio in OBS | Keep the browser source active, and check its audio routing in the OBS mixer. If you enabled **Control audio via OBS**, set up monitoring and output there. Check the levels in [Volume](/features/volume). |
| Browser player is silent | Select **Enable audio**. Make sure only the player you intend to use is open, because each job plays on one player. |
| The overlay shows an error message | The Chat TTS source is normally invisible. A message in the corner means it couldn't connect or authenticate. Copy the current URL from the dashboard. |
| Old overlay or player stops working | **Regenerate Link** replaced the token. Paste the new URL into OBS and reopen saved player links. |
