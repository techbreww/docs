Twitch TTS reads messages from a connected Twitch broadcaster's chat. It requires premium and server admin access on team servers. Its source, settings, audio queue, and overlay are separate from [TikTok TTS](/features/tts). The default voice is shared with TikTok TTS.

Twitch TTS doesn't have its own menu item. Open **Live Tools > TTS Settings** and select the **Twitch TTS** tab.

## Connect a source

1. Open **Live Tools > TTS Settings > Twitch TTS**.
2. Search for a channel in **Source Library** and select **Add source**.
3. Select **Connect channel** and authorize as the matching broadcaster.
4. Select that source for TTS. You can save several sources, but only one is active for TTS at a time.
5. Enable Twitch TTS and configure the trigger and audience. The voice is set in the **Voice** card at the top of the page.
6. Copy the overlay URL into OBS or select **Open Browser Player**.

Sources are shared with [Twitch Monitor](/features/twitch-monitor) and Integrations. Reconnect the broadcaster if the source reports an authorization error or requests additional Monitor permissions. The source library also lets you disconnect, enable/disable, or remove sources.

## Trigger and audience

**Use // prefix** requires eligible viewers to start their message with `//`. **Read messages normally** reads eligible messages without that prefix. **Allow Privileged Users Without //** grants a prefix bypass to the broadcaster, moderators, and VIPs.

| Audience | Eligible viewers |
| --- | --- |
| **Broadcaster + Moderators** | Broadcaster and moderators |
| **VIPs + Staff** | VIPs, broadcaster, and moderators |
| **VIPs + Broadcaster** | VIPs and broadcaster |
| **Everyone** | All chatters, subject to access lists |

**Whitelisted Users** can bypass audience restrictions. Whitelisting adds eligibility without removing access already granted by the selected audience. **Blocked Users** always wins: a blocked username cannot trigger TTS even if it is also whitelisted.

<Note>
  New Twitch TTS requests are skipped while the server’s Speed Tracker timer is running, even though Twitch uses a separate queue and overlay.
</Note>

## Voice settings

Twitch TTS uses the shared **Voice** card at the top of **Live Tools > TTS Settings**, the same voice, mode (**Single voice** or **Random voices**), and model as [TikTok TTS](/features/tts#voices-and-audio-tags). Changing it there changes it for both platforms.

On the **Twitch TTS** tab, assign **Custom User Voices** to give specific Twitch usernames a fixed voice that overrides the shared voice or random mode.

See [voice models and audio tags](/features/tts#voices-and-audio-tags) for expressive speech examples, and [TTS audio tags](/features/tts-audio-tags) for the full tag list.

Before speaking, BrewBot converts stylized Unicode letters, such as 𝓑𝓻𝓮𝔀𝔀 or ｆｕｌｌｗｉｄｔｈ text, into plain letters and skips emoji and decorative symbols. A message with nothing left to say, such as one made only of emoji, is skipped. See [How messages are cleaned up](/features/tts#how-messages-are-cleaned-up).

## Overlay, browser player, and queue

The **Overlay & Queue** section provides the OBS URL, preview, token regeneration, and **Browser Player** link. The browser player runs on another device with a visible queue and playback controls. Select **Enable audio** if the browser blocks playback.

**Clear pending** removes pending jobs. A player claims jobs for playback; multiple open playback sources do not mirror every message to every device. Keep the intended source audible in your streaming setup.

<Warning>
  Regenerating the token invalidates existing Twitch TTS overlay and player URLs. Replace them in OBS and on any playback devices. Keep token-bearing links private.
</Warning>

## Troubleshooting

| Symptom | Check |
| --- | --- |
| No messages are read | Confirm Twitch TTS is enabled and a source is selected for TTS. Make sure that source is enabled in **Source Library** and connected. |
| Source shows an authorization error | Select **Connect channel** and authorize again as the matching broadcaster. |
| One message isn't read | Check the trigger mode and `//` prefix, the audience, the whitelist, and the blocked list. The same viewer sending the same message again within 30 seconds is skipped. |
| Nothing is read while the timer runs | New requests are skipped while the Speed Tracker timer is running. They aren't queued for later. |
| An emoji-only message isn't read | Messages with no letters or numbers left after cleanup are skipped. |
| No audio in OBS | Keep the browser source active and check its audio routing in the OBS mixer. Check the **Twitch TTS** level in [Volume](/features/volume). |
| Browser player is silent | Select **Enable audio**. Each job plays on one player, so close players you aren't using. |
| Old overlay or player stops working | **Regenerate token** replaced the token. Paste the new URL into OBS and reopen saved player links. |
